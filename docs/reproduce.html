Reproduce

Bring it up from a cold machine.

Written for someone who has never touched this setup. If a step here does not work on a clean install, that is a bug in this page and it should be fixed.

Install

One time, in order

  1. Clone the repository

    Everything below assumes you are working from the cloned tree. Repository URL and access procedure are on the project README.

  2. Unitree SDK in a virtual environment

    Create the venv, install unitree_sdk2_python in editable mode, then add ultralytics and opencv-python for detection. All skills run inside this environment.

  3. Network profiles

    Create both connections and confirm the robot profile is not the default route. Getting this wrong is the most common failure: the robot pings, but API calls silently go nowhere.

    nmcli connection modify "Robot-GO2" ipv4.never-default yes

  4. OpenClaw and the gateway

    Install with pnpm. The gateway configuration lives at ~/.openclaw/openclaw.json and holds the Telegram token, the model selection, and the tool profile.

  5. Model credentials

    Paste the API key through the interactive command so it never appears in shell history, then confirm the model resolves.

    pnpm openclaw models auth paste-api-key
pnpm openclaw models status

  6. Install the skills

    Copy the skill folders into the agent workspace. The gateway discovers them by reading each SKILL.md at startup, so a restart is required after any change.

Every session

Startup sequence

Four steps, in this order, every time. The last one matters more than it looks: a reused Telegram thread carries the model's memory of skills that may no longer exist, and it will confidently reissue commands that were valid an hour ago. 

nmcli connection up "Robot-GO2"
ping -c 3 192.168.123.18
pnpm openclaw gateway restart      # from the openclaw directory
# then start a fresh conversation with the Telegram bot

Acceptance test

Confirm it works before you change anything

Send each message to the bot and check the result line. If all three pass, the full path from language to motor is intact and any later failure is yours, not the setup's.

Say to the bot

“Stretch.”

RESULT status=ok

Confirms the DDS link and the sport controller.

Say to the bot

“Walk forward two metres.”

RESULT status=ok distance_m=2.0

Confirms locomotion and watchdog resending.

Say to the bot

“Is there a person in front of you?”

RESULT found=true class=person

Confirms camera, CUDA and the detection model.

When it breaks

Failures we have actually hit

SymptomCauseFix
Robot pings, API calls time out Robot profile took the default route Set ipv4.never-default yes and bring the link back up
Robot moves for about a second and stops Motion command sent once Resend at roughly 10 Hz for the whole duration
Turns are far shorter than expected Yaw rate below the usable range Use the calibrated value; do not assume it scales linearly
Model searches the filesystem for a skill Stale session after a skill edit Restart the gateway and open a fresh Telegram thread
Detection misses obvious objects Inference image size too small Use imgsz=640

Handover

Backup and ownership

What to back up

The gateway configuration, the skill workspace, and the session logs. Everything else can be reinstalled from the repository.

Who to ask

Repository access, API billing and robot booking each have an owner. Names and the request procedure are in the project README so this page does not go stale.
