Reference

The words this project uses, and what they mean here.

Several terms below mean something narrower in this system than they do in general use. Where that happens, the definition given is the one that applies on these pages.

Glossary · The system

Agent and dispatch

Agent A language model given tools and run in a loop, so it can act, observe the outcome, and act again. Distinct from a single question and answer.
Gateway The OpenClaw process that receives a Telegram message, assembles the prompt, applies the tool profile, and calls the model. Everything passes through it.
Dispatcher The model acting in its role of choosing one skill per turn. Not a separate program — a description of what the model is being asked to do.
Skill A folder containing a description the model reads and a script the machine runs. The unit the model is allowed to invoke.
Skill runner The single tool that executes a named skill with parameters. Kept deliberately minimal: if it could run arbitrary code, the tool profile would mean nothing.
Tool profile The list of tools an agent may call. Enforced by the framework rather than requested in the prompt, which is what makes it reliable.
Deny list Tools explicitly withheld. Denials are applied after allowances, so a denied tool stays denied however broadly it was granted elsewhere.
Discrete dispatch One skill per turn, with the result read before the next choice. The opposite of writing a loop that runs the whole task in a single call.
Session One continuous conversation with the bot, carrying the full message history. Editing a skill mid-session leaves stale instructions in that history.
Session log A JSONL file recording every message and tool call. The authoritative record of what the model did, as opposed to what it said it did.

Glossary · The robot

Control and motion

Quadruped A four-legged robot. Locomotion is a controlled fall rather than rolling, so commands are velocities rather than positions.
Sport controller The Go2's built-in high-level controller. Accepts commands like walk, sit and stand, and handles balance and gait itself.
High-level control Telling the robot where to go and letting its own controller work out the joints. This project is entirely high-level.
Low-level control Commanding individual joint torques and positions directly. More powerful, far easier to damage the robot with. Not used here.
DDS Data Distribution Service — the publish and subscribe protocol the Go2 speaks. The workstation joins the robot's network and exchanges messages over it.
Watchdog A safety timeout in the controller. If no new command arrives for about a second it stops the robot, on the assumption the controlling program has died. Motion commands must therefore be resent continuously.
Yaw rate Rotation speed about the vertical axis, in radians per second. Turning is commanded as a rate held for a duration, not as an angle.
Open loop Acting without measuring the outcome. Walking two metres means walking at a known speed for a calculated time and assuming it worked.
Dead reckoning Estimating position from speed and elapsed time rather than observation. Error accumulates and is never corrected.
Odometry Estimating position from sensors such as wheel or joint encoders. Not used here, which is why drift accumulates.

Glossary · Perception and models

Vision and language

YOLO A family of object detection models that locate and classify objects in one pass. Fast enough to run per frame.
COCO classes The eighty everyday object categories the detection model was trained on — person, chair, bottle and so on. Anything outside that list cannot be detected.
Inference size The resolution an image is scaled to before detection. Smaller is faster and misses more; this project uses 640 pixels.
Confidence The model's own score for a detection, from zero to one. A threshold decides what counts as found, and that threshold is a choice, not a fact.
Context Everything the model can see when deciding: the instruction, the skill descriptions, and the results of previous steps in the session.
Tool call A structured request from the model to run something. The gateway checks it against the tool profile before executing it.
Result line The single line a skill prints when it finishes, beginning with RESULT and followed by name and value pairs. The model's only view of what happened.
Prompt-level rule An instruction written in the system prompt. Constrains what the model is told to do, not what it is able to do.
Architectural constraint A restriction enforced by removing the capability. The model cannot route around it, because there is nothing to route to.

Conventions

How to read the notation on this site

You will seeIt means
ALLOW The tool is available to the agent in that configuration.
DENY The tool is withheld at the framework level. Struck through in the tool lists.
monospaced text Something typed literally: a filename, a command, a parameter, or a value.
RESULT key=value Output from a skill back to the model, never the other way round.
